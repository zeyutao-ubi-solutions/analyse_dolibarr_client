# LinkedIn scraping contract (analyse_dolibarr_client ⇄ web app)

This repository provides the list of companies to scrape; the web app (Apify) scrapes the LinkedIn **company pages** and returns them in the format below; this repository then trains the lookalike model (overall model + allocation model, see `feature_policy.md`).

Company pages only; **no personal profiles of any kind** (employees, contacts, post authors).

## 1. Input: scrape list

`data/processed/<snapshot>/labeling/linkedin_scrape_list.csv` (UTF-8 BOM), generated by the command below:

```bash
uv run python -m analyse_dolibarr_client.scrape_list --snapshot <snapshot>
```

| Column | Description |
|---|---|
| `unit_id` | Primary key, returned unchanged. Either a domain (e.g. `geodis.com`) or `tp:<third-party id>` / `cust:<customer id>` |
| `batch` | `main` is scraped first; `reserve` is the spare set, scraped when the share of `main` units without a page found is high |
| `search_name` | Main search name |
| `alt_search_names` | Other names, `;`-separated (order names, other third-party record names). Try them when `search_name` finds nothing or the result looks wrong |
| `web_domain` | Known domain, **the most reliable matching basis** (see section 3) |
| `country_code` / `town` | For disambiguation: among companies with the same name, pick the one in this country / town |
| `registry_id` | Number registered in the third-party record (SIREN, SIRET or foreign tax number, uncleaned), for manual checks only |
| `has_domain` | Units without a domain can only be matched by name, with a higher risk of mismatch |

The list **deliberately has no** "is a customer" label and is not sorted by label. Scraping and matching (including any LLM judgement) must not know which units are customers; otherwise matching quality would differ by label and the model would learn a spurious signal.

## 2. Output: one row per unit_id

Return `linkedin_companies_<date>.csv` or equivalent JSONL, placed under `data/processed/<snapshot>/labeling/`.

### Match information (required)

| Column | Description |
|---|---|
| `unit_id` | From the list |
| `match_status` | `matched` / `not_found` / `ambiguous` (several candidates, unsure) / `error` |
| `match_method` | `domain` (page website domain = `web_domain`) / `name_country` / `name_only` / `manual` |
| `linkedin_url`, `linkedin_public_id` | Company page |
| `candidates` | For `ambiguous`, the candidate page URLs, `;`-separated |
| `scraped_at` | ISO time |

### Raw feature fields (as complete as possible)

| Column | Use |
|---|---|
| `description` (About) | **Main feature**. Stored as original text, not translated or truncated; language is handled by this repository |
| `tagline` | Auxiliary text feature |
| `specialties` | Auxiliary text feature, `;`-separated, original text |
| `industry` | Auxiliary feature (LinkedIn industry, raw value; English code or label are both fine, but be consistent) |
| `employee_count`, `employee_count_range` | Size |
| `company_type` | Public / private / government / non-profit… |
| `founded_year` | |
| `followers` | |
| `locations_count` | Count only |
| `has_parent_or_affiliated` | Whether there is a parent company / affiliated pages |
| `parent_linkedin_url` | Filled when there is a parent company, used to tell whether a group page was scraped |

### Fields for checking only, not used in the model

| Column | Use |
|---|---|
| `name` | Check the match |
| `website` | Check the match (compare with `web_domain`) |
| `hq_country`, `hq_city` | Only for country weighting and per-country evaluation; **not in the model** (country proxy) |

Do not return: employee lists, contacts, phone numbers, emails, posts.

## 3. Matching rules (tightened after the 2026-11-20 pilot)

Of 20 units in the pilot, 13 were "matched", and manual review found 7 of those wrong or doubtful (foreign companies with the same name, a group investment-banking page, trade-union pages). Principle: **prefer not_found / ambiguous over padding with the wrong page**: a mismatch directly pollutes the labels, while a miss only loses one sample.

### 3.1 What to search (in order, until one result passes 3.2)

1. When `web_domain` is present, first search the domain stem as a brand name (`aroihoteles.com` → `aroihoteles`, `360hostel.com` → `360hostel`): legal names often return nothing, brand names are closer to the name on LinkedIn.
2. `search_name`, then `alt_search_names` in turn.
3. If the actor can return several candidates at once (e.g. `maxItems` / limit), take the first 3–5 and judge each per 3.2; if it returns only the first result, judge only that one.

### 3.2 What counts as matched

| Case | Result |
|---|---|
| Main domain of the page website (eTLD+1, without `www.` and subdomains, e.g. `fr.scc.com` → `scc.com`) = main domain of `web_domain` | `matched`, `match_method=domain` |
| `web_domain` present, page website is a **different** domain | **Not matched**. If name and country both match → `ambiguous` (goes to the manual queue), otherwise → next candidate / `not_found` |
| Page has no website | `matched` only if "identical normalised name + HQ country = `country_code`" (town must also match when `town` is present), `match_method=name_country`; otherwise `ambiguous` |
| No `web_domain` | Same as above: identical normalised name + same HQ country → `name_country`; name only partly the same → `ambiguous` |
| `country_code` empty | **Never automatically matched**, at most `ambiguous` (`name_only` no longer counts as matched) |
| HQ country ≠ `country_code` | Not matched; `ambiguous` if the name is identical, otherwise `not_found` |
| Not the company's own page: trade unions (SYNDICAT, CGT, CFDT, FO), CSE / works councils, alumni / campus, fan pages | Reject, next candidate / `not_found` |

"Normalised name": compare after removing accents, case, punctuation and legal form (this repository's `analyse_dolibarr_client.names.core_key` can be used).

### 3.3 Extra flags (do not affect matched, but must be returned)

| Column | Meaning |
|---|---|
| `group_page` | The domain matched, but the page name and the list name share no word (e.g. a subsidiary's domain points to the group page). Can be checked with `names.names_unrelated` |
| `thin_page` | Employee count ≤ 1 and no website, or description shorter than 20 words |
| `query_used` | The search term that actually hit (from `originalQuery.search`) |

### 3.4 Manual queue

Write every `ambiguous` unit to `linkedin_review_queue.csv`: `unit_id`, the name / domain / country / town from the list, and for each candidate its URL / name / website / HQ country / town. Only manually confirmed units can go into training; unconfirmed ones are not used.

The matching rules treat all units the same and must not differ by whether a unit is a customer (the list does not contain this information anyway). After the full run, this repository computes match rates separately for customers / prospects to check for systematic differences.

## 4. What this repository does on receipt

- Merge labels by `unit_id`; train only on `matched` units.
- **Recompute** `sample_weight` with the units actually scraped (`lookalike.add_country_weights`), since the not-found share may differ by country.
- description / tagline / specialties are all processed with a multilingual embedding model (synonymous texts in different languages land in the same place); no raw bag-of-words, no language itself.
- Run the country leakage check before training (`feature_policy.md`).
